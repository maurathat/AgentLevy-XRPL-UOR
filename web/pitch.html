    The thesis

    The internet wasn't built for 100 agents per human.

    Coframe's site says it: soon, for every human, 100 agents will use the internet. If every one of those agents has its own ChatGPT or Claude subscription, the economy collapses — subscriptions don't scale to autonomous buyers. If they share memory via content-addressed receipts, the economy works.

    RoyaltAI is the protocol for that. Pay-per-call AI inference with cryptographic memoization and royalty enforcement to model creators. The first MCP-native trust layer for agent commerce.

    1Subscriptions break for autonomous agents.
    2The same answer paid for repeatedly is a cost-explosion at 100×.
    3Content-addressed memory + per-call payment = the only economics that scales.
    How it works

    Three beats. Same answer, second agent, tenth the cost.

    1

    Agent A pays

    Agent A submits a request. Server computes the UOR address from model + prompt + hour bucket via JCS-RFC8785 + SHA-256. 402 quote: 0.010 XRP.

    Agent pays on XRPL with the UOR address in the memo. Server verifies the payment, runs Anthropic, signs a DerivationCert, anchors to Hedera HCS, routes 50 % royalty to the model NFT owner.

    2

    Agent B asks the same question

    Different wallet. They've never heard of Agent A. But the canonicalization is deterministic per UOR-ADDR-1, so both agents arrive at the server with the same UOR address.

    Server checks its cert store: cache hit. 402 quote: 0.001 XRP — ten times cheaper. No Anthropic call. The model creator still earns royalty on the cache hit.

    Reference · VTEAI

    Verified Task Escrow + Attestation Interface.

    The ERC draft I authored in April. Defines the on-chain settlement interface for agent commerce — escrow a payment, commit to a task hash, release on verifier attestation. Chain-neutral. CC0-licensed. The standard underneath both AgentLevy on Base and RoyaltAI on XRPL.

    What VTEAI standardizes
    • TaskSpec hash content commitment to acceptance criteria, verification manifest
    • Attestation hash verifier-signed proof that work matched the spec
    • Settlement interface escrow → commit → release pattern; payout method-agnostic (push or pull)
    • Composability verifier trust model is implementation-specific — deterministic server, TEE, decentralized verifier, FDC, all allowed

    Reference · audit chain anatomy

    Three independent witnesses on every cert. Verifiable in 2046 from public keys alone.

    Request
    JCS(deep_NFC({ model, prompt, hour_bucket }))
    → sha256:<64 hex> = request UOR address
    ↓ signed by inference server
    DerivationCert
    Ed25519 signature over { request_uor, model_nft, response_bytes, timestamp }
    → cert UOR address
    ↓ anchored to three independent witnesses
    XRPL Mainnet
    Payment txid records UOR address in memo. Real-money settlement is the witness.
    Hedera HCS
    Cert UOR submitted to topic 0.0.8856047. Consensus timestamp + sequence number = tamper-evident ordering on a chain independent of XRPL.
    UOR Foundation MCP
    Live byte-identity check: server's computed address verified byte-equal to canonical Rust reference. ed25519 receipt signed by Foundation.
    What a regulator does in 2046 to verify a 2026 cert
    1. Re-canonicalize the request bytes with JCS + NFC + SHA-256 (UOR-ADDR-1, 5 lines of Python).
    2. Ed25519-verify the cert signature with the inference server's public key.
    3. Hash the response bytes; confirm match against cert's output content address.
    4. Pull Hedera HCS message at the recorded sequence number; confirm cert UOR address matches.
    5. Pull XRPL transaction by txid; confirm memo contains the UOR address.

    No vendor needs to be online. Anthropic could be acquired, AgentLevy could shut down, this server could be offline — the cert chain still verifies because the witnesses are independent public ledgers and a foundation-adopted standard.

    The design insight

    The agent doesn't search for the address — it computes it.

    Content addressing is deterministic by design. Same canonical input always produces the same SHA-256. Agent A computes the address when it asks. Agent B computes the same address when it asks. The server's cache lookup is O(1) — no search, no discovery, no consensus needed.

    The only real discovery problem is which server has the cert I want. That's solved by MCP servers acting as agent-native resolvers — the same way DNS resolves URLs for human-driven browsers.

    UOR-ADDR-1 is the URI of the Internet of Agents. MCP is its DNS.
    Phase 4 · The substrate composes

    Bolt this under a KYC workflow and every LLM call gets its own receipt.

    Today's compliance audit proves the work happened. It cannot prove which model produced the determination. Stack the inference cert chain underneath the compliance cert chain — same UOR-ADDR-1 primitive at both layers — and the regulator can walk from "this sanctions result was signed by this agent" down to "this exact model produced this exact extraction, paid for in this exact RLUSD transaction, with royalty routed to this exact model NFT."
